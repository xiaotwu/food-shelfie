# Shelfie 产品与工程评估

> 本文保留 2026-09-29 的历史评估，正文中的“仍需改进”及发布记录反映当时状态。2026-09-30 的实现、测试证据与未完成验收请查看[最新产品改进验收清单](PRODUCT_COMPLETION.zh-CN.md)。该清单不重新核实 App Store 发布状态。

评估日期：2026-09-29。依据当前仓库、App Store Connect 拒审信息、自动化测试和 iPhone 15 Pro / iOS 27.0 启动验证。未完成的真机流程、iPad 布局、跨设备同步不视为已验证。

## 产品判断

核心定位清楚：帮助个人和家庭知道厨房里有什么、先吃什么，减少遗忘造成的浪费。无需注册、默认本地存储、手动录入加扫码、小组件，适合轻量日常使用。功能已经足够首发；下一步的价值主要来自减少录入成本、让提醒可信、避免数据丢失，而非再增加更多图表或装饰。

建议核心路径：30 秒录入第一件食品 → 首页明确显示“今天先吃这些” → 提醒后直接标记吃完 → 下次购物前查看库存。当前路径偏向完整表单和浏览，尚缺数量与部分消耗，因此真实厨房里“6 个鸡蛋吃了 2 个”的场景无法准确表达。

## 仍需改进与验证

### 首发质量：高优先级

1. **保存失败反馈仍不统一。** 食品录入、标记吃完／丢弃、分类管理等路径还有 `try? modelContext.save()`，数据库失败时可能仍显示操作成功。建议统一数据写入服务，成功后再关闭表单、更新小组件，失败保留输入并提供重试；不要只增加日志。
2. **CloudKit 生产结构已补齐，同步仍需真机证据。** 已对实际容器 `iCloud.com.xiaotwu.shelfie` 初始化食品／分类／位置／搜索四类数据结构并部署到生产环境，部署界面确认成功。初始化工具仅存在于 DEBUG 构建且由显式启动参数触发，使用独立空数据库。仍需验证 TestFlight 构建、两台设备的新增／编辑／删除与照片同步；当前不能宣称已完成跨设备测试。用随机 UUID 表示默认分类／位置，在多设备各自首次启动后可能出现重复默认记录；应设计稳定身份、去重与冲突合并。
3. **扫码恢复体验。** 网络失败后同一条码被 `lastBarcode` 去重，缺少明确重试路径。拒绝相机权限后应提供系统设置入口；扫不到条码时应提供手动输入。商品图片超时不能卡住录入，最好独立设置超时与取消。
4. **日期解析覆盖不足。** 目前纯数字斜线日期按日/月/年解析，面向美国用户可能把 03/04/2026 解释错；缺少中文“生产日期／保质期／年/月/日”规则；无效日期可能被 Calendar 归一化。建议显示识别原文、候选日期及歧义提示，让用户确认，不自动猜保质期。
5. **无障碍与适配。** 需实际检查最大字体、VoiceOver、减少动态效果、iPad 横屏／分屏。多个界面使用固定间距、自制悬浮导航和持续动画，仅编译通过不能证明可用；优先避免按钮被遮挡、字体截断与信息只靠颜色表达。
6. **数据备份版本化。** 新增字段之前建立迁移策略与历史备份样本；导入需补充损坏文件、较大图片、磁盘不足、保存失败、缺失引用等测试。当前测试验证了版本/重复 ID 拒绝与基本恢复，但不涵盖系统存储故障注入。
7. **提醒边界。** 新提醒修复了名单过时，但用户连续 28 天不打开应用后预生成提醒会耗尽。长期方案可按食品的重要日期安排有限请求，并明确无库存时是否需要每日提醒。权限拒绝后设置界面应显示真实系统状态，不只显示应用开关。跨午夜、时区／夏令时和 iCloud 远端修改后刷新还需测试。

### 下一版：最有价值的新增功能

| 建议 | 具体用户价值 | 建议验收方式 |
| --- | --- | --- |
| 数量／单位／部分消耗 | 表达“牛奶剩半瓶”“鸡蛋剩 4 个” | 减少数量不会把整批标记吃完，归零后正确更新统计 |
| 相同商品快速再次添加、复制上一条 | 同一种食物每周购买无需重新填表 | 保留分类/位置，重设购买日，明确输入新批次到期日 |
| 批次管理与开封日期 | 同商品不同到期日分开管理，开封后可设另一个提醒 | 到期与开封后期限分别可见，先用最早批次 |
| 撤销吃完／丢弃、已处理历史入口 | 减少误触，增强用户对操作的信任 | 撤销恢复原数量、状态、提醒和统计 |
| 首页“先吃这些”行动区 | 将过期数据转为下一顿饭的行动 | 第一屏可看到最紧迫食品并直接处理 |
| 本地购物清单与低库存提示 | 用户购物前不用凭记忆重复买 | 可由缺货食品加入清单，保留自定义条目 |
| 提醒直接操作和小组件深链 | 从通知或小组件迅速查看对应食品 | 点击进入正确食品详情，标记后立即刷新 |

家庭共享可作为后续重点，但当前 iCloud 是个人 Apple 账户同步，不等于家庭共享。CloudKit 分享、权限、删除边界和冲突处理需独立设计。AI 食谱、社交、积分和订阅暂不优先，直到核心记录与使用习惯得到验证。

## 衡量产品进展

优先关注首次添加完成率、添加一件食品所需时间、每周回访和处理到期食品的比例。无追踪定位下先用自愿访谈与 TestFlight 反馈，不为了度量立即接入分析 SDK。当前 anti-waste rate 基于记录中的吃完/丢弃数量，并不能证明真实减少了多少浪费；避免把它宣传成重量、金钱或碳排节省。
